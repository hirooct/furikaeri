# まなびの振り返り

児童の振り返りを授業ごとに蓄積する、Google Apps Script と Google スプレッドシートのウェブアプリです。1学級につき1つのスプレッドシートとウェブアプリを用意します。複数の先生を同じ学級の教師として登録できます。

## 初回導入

1. 学校の Google Workspace アカウントで、空のスプレッドシートを作成します。
2. **拡張機能 → Apps Script** を開きます。既存のコードファイルに `src/Code.gs` を貼り付け、HTML ファイル **Index** を追加して `src/Index.html` の内容を貼り付けます。プロジェクト設定でマニフェストを表示し、`src/appsscript.json` の内容を貼り付けます。
3. エディタで `setup_` を選んで一度実行します。承認後、名簿・単元・振り返り・先生の返信の4シートが作られます。すでにあるシートは保持されます。
4. **名簿**に、学校メールアドレス、表示する氏名、役割（`teacher` または `student`）、出席番号を入力します。最初の管理者行の氏名は編集できます。メールは1人につき1行です。児童にはスプレッドシートを共有せず、ウェブアプリのURLを配布します。共同担当の先生もアプリから利用できます。名簿とスクリプトの編集権限は管理者が管理してください。
5. **デプロイ → 新しいデプロイ → ウェブアプリ**で、実行ユーザーは**自分**、アクセスは**組織内**を選びます。発行された `/exec` のURLで、管理者、別の教師、児童2名、名簿にないアカウントを試します。学校のポリシーによりメールアドレスが取得できない場合はアクセスを拒否します。学校の管理者と設定を確認してください。
6. 先生用ページで単元を登録します。試用例は「体育」「ハードル走」「4時間」「どうすれば、ハードルをとびこえて、より速くゴールすることができるだろうか」です。

## 授業での使い方

- 教師は単元の質問を追加・編集できます。記述、単一選択、複数選択に対応します。記述では例文を1行1件で登録できます。文づくりでは候補グループを作り、文の型に `{1}`、`{2}` のように候補を差し込む場所を書きます。
- 児童は教科・単元・第○時を選んで保存します。前時までの記録と先生の返信を読み返せます。保存済みの振り返りは本人が編集できます。
- 教師は「この時間の全児童」と「児童個人」を切り替えられます。各教師が振り返りごとにコメント1件とスタンプ1つを保存・変更できます。児童を選ぶと、その単元の児童別PDFを保存できます。
- 保存時の質問と選択肢は、その記録に残ります。単元設定の編集は新規回答から適用されます。未提出の児童も含め、全員に同じ質問で答えてほしい授業時は、提出が始まる前に設定してください。
- 上限は単元100時間、質問100件、選択肢や例文は各欄100件です。スプレッドシートのセル容量に収まるよう、質問や候補、回答が長い場合は保存時にも確認します。

## AI所見案を有効にする場合

学校で利用を認められた OpenAI API のキーを、Apps Script の **プロジェクトの設定 → スクリプト プロパティ**に `OPENAI_API_KEY` として登録します。任意で `OPENAI_MODEL` を指定できます。既定は `gpt-4.1-mini` です。APIキーがない間は画面にAIボタンが表示されません。キーの共有先はプロジェクトの管理者に限定してください。

教師は選んだ児童の振り返りをもとに、送信前の文章を確認・編集できます。アプリは名簿の氏名・メールを自動で加えませんが、振り返り本文に含まれる個人名などは送信前に確認してください。AI所見は編集可能な下書きとして画面に表示し、スプレッドシートには自動保存しません。

## 更新と配布

- GitHubでソースを編集する場合は `src/` を管理します。名簿データ、APIキー、学校のスクリプトIDを含む `.clasp.json` はコミットしません。
- clasp を使う場合は既存のスプレッドシート紐づきプロジェクトのスクリプトIDを `.clasp.json` に設定し、`rootDir` を `src` にして `clasp push` します。更新後は **デプロイを管理 → 既存のデプロイを編集 → 新バージョン**を選ぶと同じURLで使えます。
- 配布用のスプレッドシートを作るときは、空の名簿と初期設定用のコードを入れた配布専用原本を用意します。受け取った先生は原本をコピーし、上記の初回導入の手順3〜5を行います。運用中の学級シートは配布原本に使いません。

## 動作確認

`node --test test/core.test.cjs` で主要な保存処理とアクセス制御を模擬確認できます。学校環境での初回確認では、児童2名の記録が混ざらないこと、未登録アカウントが拒否されること、教師2名の返信が表示されること、日本語PDFが開けることを順に確認してください。AIを使う場合は、架空データで先に生成を確認してください。
